# 《风起地的冰水协奏》设计文档

## 项目定位

《风起地的冰水协奏》是一个仅供个人试玩与学习的非商业同人原型。它使用提瓦特世界观、蒙德风起地区域、神里绫华与芙宁娜，但不使用官方截图、立绘、解包素材或原始音频。正式视觉资源由 image2 生成，再经过项目内的像素化、裁切和尺寸归一流程处理。

首个版本是一段 10-15 分钟的桌面浏览器垂直切片。目标是完成可玩的探索、交互、双角色切换、元素冻结反应、普通战斗和 Boss 战闭环，而不是复刻完整的原作系统。

## 玩家体验

风起地附近出现异常冰雾与水元素共鸣。神里绫华和芙宁娜从冒险家营地出发，调查沿途异变，清理丘丘人哨站，并在风起地树下击败受到元素紊乱影响的丘丘暴徒。

核心循环：

1. 探索半开放地图，与 NPC 和发光调查点交互。
2. 击败水史莱姆、冰史莱姆和丘丘人。
3. 在绫华与芙宁娜之间实时切换，使用冰、水技能触发冻结。
4. 推进三段任务目标，解锁风起地树下的 Boss 场地。
5. 击败异常丘丘暴徒并返回营地，完成试玩。

首版不加入抽卡、装备养成、背包、存档、支线任务、手机触屏和多人玩法。

## 地图结构

地图是一张精致 32-bit 像素风半开放区域，使用跟随当前角色的俯视角镜头。区域通过小型环路连接：

```text
冒险家营地
   |
草地岔路 ---- 丘丘人哨站
   |              |
风之遗迹调查点 -- 风起地树下 Boss 场地
```

地图包含青绿草地、风车菊、碎石小径、残破石柱、木制营地、树丛和风起地大树。Boss 场地在任务目标完成前保持封锁，并提供明确提示。

## 角色与输入

桌面键盘输入：

| 按键 | 动作 |
| --- | --- |
| `WASD` | 八方向移动 |
| `J` | 普攻 |
| `K` | 元素战技 |
| `L` | 元素爆发 |
| `Q` | 切换角色 |
| `E` | 与 NPC、调查点和任务目标交互 |
| `Space` | 冲刺，消耗体力并短暂加速 |
| `Escape` | 暂停或关闭当前面板 |

绫华：

- `J`：三段近战剑击。
- `K`：冰华斩，在前方造成冰元素伤害并附着冰。
- `L`：霜灭，释放向前移动的冰风暴。
- 定位：近战爆发、冻结后的主要输出。

芙宁娜：

- `J`：发射远程水波。
- `K`：召唤三位沙龙成员，在短时间内自动攻击附近目标并附着水。
- `L`：众水的歌剧，造成范围水元素伤害，并短暂提高全队伤害。
- 定位：远程牵制、持续挂水、辅助增益。

角色切换带有短冷却。当前角色阵亡时自动切换，双角色均阵亡后从营地重新开始本次试玩。

## 战斗规则

首版只实现完成核心体验所需的水、冰附着与冻结反应：

- 敌人受到水元素或冰元素伤害后获得短暂元素附着。
- 敌人同时具有水与冰附着时进入冻结。
- 普通敌人冻结时停止行动。
- Boss 冻结时只受到短暂减速和额外削韧，避免战斗失去挑战性。

敌人配置：

- 水史莱姆、冰史莱姆：教学元素附着与冻结。
- 丘丘人战士、丘丘人射手：构成哨站战斗。
- 异常丘丘暴徒：Boss，拥有冲锋、挥击和范围震地三种招式。

## 界面

游戏世界由 Phaser canvas 渲染。文本密集的界面使用 DOM 覆盖层：

- 左上角：当前任务目标。
- 右上角：区域名称和控制提示入口。
- 左下角：当前角色头像、生命值、体力条。
- 右下角：普攻、战技、爆发和切换角色的按键提示与冷却状态。
- 底部：像素风对话框。
- 暂停状态：展开控制说明。
- 首次战斗：显示短暂冻结反应提示。

HUD 使用蒙德郊外的清爽青绿、水蓝和冰蓝色调。中心区域与下方中间区域不放常驻面板，避免遮挡战斗。

## 美术资产

正式资源使用 image2 生成，风格统一为精致 32-bit 像素画。项目保存生成源图和运行时处理后的资源：

```text
assets/source/
  characters/
  enemies/
  environment/
  fx/
  ui/
public/assets/
  characters/
  enemies/
  environment/
  fx/
  ui/
```

首版资产清单：

- 绫华探索与战斗精灵源图、头像。
- 芙宁娜探索与战斗精灵源图、头像。
- 水史莱姆、冰史莱姆、丘丘人战士、丘丘人射手、丘丘暴徒。
- 草地场景、碎石路、石柱、木箱、帐篷、灌木、风车菊、风起地大树。
- 冰斩、水波、冰风暴、冻结状态、Boss 震地等技能特效。
- 对话框、任务标记和 HUD 装饰。

生成源图进入 `assets/source/`。经过裁切、透明背景处理、像素化、尺寸归一和锚点校准后，运行时资源输出至 `public/assets/`。动画帧不足时优先使用轻量补间，不伪造完整帧动画。

## 技术架构

技术栈为 Phaser、TypeScript、Vite 和 DOM HUD。玩法状态与 Phaser 场景分离：

```text
src/
  assets/
    manifest.ts
  game/
    config.ts
    main.ts
    scenes/
      BootScene.ts
      WorldScene.ts
    systems/
      CombatSystem.ts
      GameState.ts
      InputMap.ts
      QuestSystem.ts
    data/
      map.ts
      actors.ts
  ui/
    hud.ts
    styles.css
  main.ts
```

模块职责：

- `BootScene`：加载清单中的像素资产，失败时继续启动。
- `WorldScene`：渲染地图、角色、敌人、碰撞、镜头和特效。
- `GameState`：保存任务阶段、当前角色、生命值、体力、元素附着和战斗结果。
- `CombatSystem`：处理伤害、冷却、命中、冻结与 Boss 削韧。
- `QuestSystem`：管理营地对话、调查点、哨站战斗、Boss 解锁和返回营地。
- `InputMap`：统一映射键盘输入为游戏动作。
- DOM HUD：展示任务、角色状态、技能冷却、对话和暂停面板。
- `assets/manifest.ts`：通过稳定键名引用 image2 生成的资源。

运行时资产加载失败时显示像素风占位图形，不阻止游戏启动。

## 验证策略

自动化验证：

- 为水、冰附着和冻结规则编写单元测试。
- 为 Boss 冻结减速与削韧规则编写单元测试。
- 为角色切换冷却和角色阵亡自动切换编写单元测试。
- 为任务阶段推进和 Boss 区域封锁编写单元测试。
- 运行类型检查和生产构建。

浏览器验证：

- 从营地开始并完成完整任务流程。
- 覆盖探索、交互、普通战、角色切换、冻结、Boss 战、返回营地。
- 截图检查 HUD 遮挡、角色比例、技能可读性、地图路线和对话布局。
- 检查常见桌面窗口尺寸下的界面表现。

## 完成标准

第一阶段完成时，玩家能够在桌面浏览器中从营地开始，在 10-15 分钟内完成完整任务；两名角色均可实时操作和切换；冻结反应、普通敌人、Boss 战、任务推进与结束对话均可实际体验；正式像素美术资源由 image2 生成并接入运行时；测试、类型检查、生产构建与浏览器试玩均完成验证。
